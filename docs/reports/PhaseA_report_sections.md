## Module 4 — Streaming System
Replay batches of the time-ordered stream are published by a producer to the Kafka topic `network-events` (single partition, because ordering is the point of a time-ordered stream) and scored by a consumer holding the deployed model behind a swappable `ModelHolder`; predictions and confidences go to `predictions`. A message carries one batch as zlib-compressed little-endian float32 plus metadata; labels travel in a separate field that the scorer never decodes, so label-delay policies can be enforced. Delivery is at-least-once (acks=all, idempotent producer, offsets committed after the prediction is published) and the scorer is idempotent on batch index, so redelivery has no effect; a gap in indices is an error. **Equivalence:** predictions and confidences obtained through the pipeline were bit-identical to the in-memory Phase 3 loop [REAL: Kafka run pending], including with injected duplicates. **Latency:** [REAL: table from `phase4_latency_kafka.csv`; model time per 1000 flows feeds the Latency term of the controller utility]. An in-memory transport with the same code path is the fallback.

## Module 2 — Synthetic Concept-Drift Generator
Six scenario types (abrupt, gradual, recurring, temporary, incremental, novel-class) plus a drift-free control are generated from a class-indexed pool of real flows with recorded ground truth (change points, segments, affected classes and features, magnitude). Class-mix changes are *prior/label-distribution shift*; bounded additive offsets on informative features are *synthetic covariate shift*; their combination is synthetic concept drift, not naturally occurring drift (limitation §9.3). Three magnitude levels differ only in strength, not in which drift occurs. Validation and test scenarios use disjoint flow pools and different seeds. Calibration against the static model's degradation: [REAL: `phase5_magnitude_calibration.csv`].

## Module 5 — Drift Detection
ADWIN (per-flow error bits; theoretical false-positive guarantee), Page–Hinkley (per-batch error rate), PSI (reference-quantile bins, mean of the 5 largest per-feature PSIs), MMD (RBF, median heuristic, subsampled, null-calibrated threshold) and, as an extra label-free signal, ADWIN on prediction confidence; fused as D = Σ wᵢ·min(sᵢ,1). Error-based detectors observe labels delayed by k=2 batches. Each detector's operating parameter and the fusion weights/θ were tuned on validation scenarios only with J = detection rate − 0.02·FA/1000 − 0.002·delay, frozen, then evaluated on test scenarios (6 seeds × 3 magnitudes × 6 kinds + controls) with a 10-batch tolerance window. Results: [REAL: `phase6_detector_comparison.csv`, `phase6_detector_by_scenario.csv`; mean±std over seeds in `phase6_detector_seed_stats.csv`; fusion vs single: Wilcoxon in `phase6_fusion_vs_single_wilcoxon.csv`]. Whether fusion reduces false alarms is reported as measured, not assumed.

## Module 6 — Drift Analyzer
For each detected event a `DriftSignature` is produced from at most 8 batches after the alarm (no look-ahead): magnitude (PSI/MMD in units of their thresholds), persistence, duration, ended flag, type guess, confidence-based novelty, per-feature PSI vector and recurrence (cosine similarity to stored signatures). Evaluation against truth: [REAL numbers]. Known limitations to state: novelty from confidence is not specific to new classes; the temporary-vs-abrupt distinction needs the revert to be observable within the look-ahead; incremental drift is reported as gradual.
